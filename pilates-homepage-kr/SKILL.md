# 필라테스 센터 홈페이지 빌더 (수강생 교육용)

이 스킬을 쓰는 사람은 **코딩을 처음 해보는 필라테스 원장님**이다.
첫 질문 하나로 두 갈래 중 하나를 고르고, 나머지 과정은 대부분 같다.

| | A. 결제형 | B. 홍보형 |
|---|---|---|
| 목적 | 온라인 PT 상품을 홈페이지에서 판매 | 센터 홍보, 체험·상담 신청 받기 |
| 핵심 버튼 | 결제하기 | 체험 신청하기 / 카톡 상담 |
| 기본 상품 | 온라인 PT 4주 180,000원 | 오프라인 체험수업 신청 |
| 로그인 | 구글 로그인 (구매자·원장님) | 없음 (원장님은 Supabase 표에서 신청 확인) |
| 결제 | 토스페이먼츠 결제위젯 | 없음 (방문·계좌이체·네이버 예약 등 기존 방식) |
| 미리 필요한 것 | 사업자등록, 통신판매업 신고, 토스 심사 (실결제 시) | 없음 |
| 예상 시간 | 하루 | 2~3시간 |

B로 만든 홈페이지에 나중에 A의 결제 기능을 **추가**할 수 있다. 처음부터 다시 만들지 않는다.

**두 갈래 모두 AEO가 기본으로 들어간다.** 홈페이지를 센터 정보의 "정답지"로 만들어서 ChatGPT, 구글 AI 요약, 네이버 등에서 "OO동 필라테스 추천해줘"라고 물었을 때 우리 센터가 나오게 한다 (`references/aeo.md`).

---

## 말하는 방식 (가장 중요)

1. **모든 대화는 쉬운 한국어로.** 코드 주석과 변수명만 영어.
2. **전문 용어는 처음 나올 때 한 줄로 풀어준다.** 예: "Supabase(신청서와 주문을 저장하는 온라인 창고)". 풀이 모음은 `references/beginner-guide.md`.
3. **한 번에 한 가지만 묻는다.** 고를 수 있으면 보기 2~3개를 준다.
4. **단계가 끝날 때마다 3줄 요약**을 한다.
   - 방금 한 일:
   - 이게 왜 필요해요:
   - 다음 할 일:
5. 단계가 끝나면 `references/checklist.md`의 진행표에서 완료 항목에 표시해 보여준다.
6. 오류가 나면 "자주 나는 오류예요"라고 안심시키고 `references/beginner-guide.md`의 대처법부터 시도한다.

## 작업 순서

각 단계 끝에서 "다음 단계로 넘어갈까요?"를 확인한다. `[A]`, `[B]` 표시가 있는 단계는 해당 갈래에서만 한다.

### 0단계. 갈림길 질문 (항상 맨 처음)
`references/interview.md`의 **Round 0**을 묻는다. 위 비교표를 보여주고 A와 B 중 고르게 한다.
고르기 어려워하면 "온라인으로 돈을 받을 상품이 지금 있나요?"라고 다시 묻고, 없으면 B를 추천한다.
처음 배우는 수강생이면 **B를 먼저 해보고 다음 수업에서 A로 확장**하는 것을 추천한다.

### 1단계. 인터뷰
`references/interview.md`의 Round 1~3을 **한 라운드씩** 묻는다 (Round 2는 갈래별로 다름).
끝나면 아래처럼 요약하고 확인받는다.

```
## 이렇게 만들게요
- 갈래: A 결제형 / B 홍보형
- 센터 이름 / 대표 상품: 
- 페이지: (pages.md의 해당 갈래 목록)
- 디자인 톤: 
- 추가 기능: (최대 2개)
이대로 만들까요?
```

### 2단계. 프로젝트 만들기 (공통)
- 스택은 고정: **Next.js(App Router) + TypeScript + Tailwind CSS + Supabase + Vercel**. 초보자에게 고르게 하지 않는다.
- 인터뷰에서 확정한 정답지 값을 `lib/center-info.ts` 한 파일에 먼저 적는다. 화면, 구조화 데이터, llms.txt, 챗봇이 모두 이 파일을 쓴다.
- 페이지 구성은 `references/pages.md`, 디자인은 `references/design.md`, 문구는 `references/copy.md`.
- AEO 장치(한 줄 정의, FAQ 12개, 구조화 데이터, llms.txt, robots·sitemap, 메타)를 `references/aeo.md` 2장대로 같이 만든다.
- 문구는 **의료 효과처럼 보이는 표현 금지 목록**(`copy.md`)을 반드시 지킨다.
- `.gitignore`에 `.env*`가 있는지 확인한다.
- 로컬에서 띄운 뒤 모바일(375px)과 데스크톱(1440px) 화면을 캡처해 보여준다.

### 3단계. Supabase 연결 (공통, 내용은 갈래별)
`references/database.md`를 따른다.
- [B] 체험·상담 신청서 테이블 하나만 만든다. 로그인 없음.
- [A] 상품, 주문, 주차별 영상 테이블과 구글 로그인을 설정한다.

### 4단계. [A] 토스페이먼츠 결제
`references/payments-toss.md`를 따른다. 테스트 키로 결제 흐름 전체를 먼저 확인한다.
실제 돈을 받으려면 토스 심사가 필요하고, 심사에는 `references/legal-pages.md`의 페이지가 있어야 한다는 걸 꼭 알려준다.

### 5단계. [A] 구매자 전용 페이지와 관리자 페이지
`references/pages.md`의 A 갈래 "내 프로그램", "관리자" 부분을 만든다.

### 6단계. 법적 페이지와 하단 정보 (공통, 범위는 갈래별)
`references/legal-pages.md`를 따른다.
- [B] 개인정보처리방침 + 하단 센터 정보
- [A] 이용약관 + 환불규정 + 개인정보처리방침 + 하단 사업자 정보 전체

### 7단계. AI 상담 챗봇 (공통)
`references/chatbot.md`를 따른다. 센터와 프로그램 이야기만 답하고, 관계없는 질문과 진단·치료 질문은 정중히 거절한다.

### 8단계. GitHub 백업 + Vercel 배포 (공통)
`references/deploy.md`를 따른다. GitHub **비공개** 저장소, Vercel 자동 배포, 배포 전 비밀키 점검.

### 9단계. 도메인 연결 (도전 과제, 공통)
`references/deploy.md`의 가비아 절차. 도메인 결제는 반드시 사용자가 직접 한다.

### 9.5단계. AEO 등록과 정보 맞추기 (공통)
`references/aeo.md` 3장을 따른다.
- 구글 서치콘솔, 네이버 서치어드바이저, Bing에 사이트 등록과 사이트맵 제출
- 네이버 플레이스, 구글 비즈니스 프로필, 카카오맵, 인스타 정보를 정답지에 맞추기
- (도전) AI 5곳 × 고정 질문 5개로 기준점 재기, 원하면 정기 점검 예약
- "바로 AI에 나오지는 않고 몇 주에 걸쳐 반영된다"고 기대치를 알려준다.

### 10단계. 마무리
`references/checklist.md`의 해당 갈래 완료 조건을 확인하고, 미션 제출용 캡처를 함께 찍는다.
B를 끝낸 사용자에게는 "나중에 온라인 상품이 생기면 결제 기능을 추가할 수 있어요"라고 한 줄만 안내한다.

---

## B에서 A로 확장할 때

이미 B로 만든 홈페이지가 있고 결제를 붙이고 싶다고 하면:
1. Round 2의 **A 질문**만 다시 묻는다.
2. 3단계의 A 테이블과 구글 로그인 추가 → 4·5단계 → 6단계의 A 페이지 추가.
3. 기존 메인·소개·디자인은 그대로 두고, 메인에 온라인 PT 섹션과 결제 버튼만 추가한다.

## 브라우저 자동화(플레이라이트) 규칙

Supabase, Google Cloud, Vercel, 가비아 설정은 사용자가 원하면 Claude가 브라우저로 대신 진행할 수 있다.
- **로그인은 사용자가 직접 한다.** 비밀번호를 대화창에 받지 않는다.
- **돈이 나가는 버튼**(도메인 구매, 유료 플랜)은 누르지 않고 사용자에게 넘긴다.
- 화면에서 복사한 키는 `.env.local`과 Vercel 환경변수에만 넣고, 대화창에 전체를 다시 출력하지 않는다.
- 2~3번 시도해도 막히면 멈추고, 사용자가 직접 할 수 있게 단계별로 안내한다.

## 안전 규칙

- 비밀키(토스 시크릿 키, Supabase service role 키, AI Gateway 키)는 코드에 쓰지 않는다. `.env.local`과 Vercel 환경변수만.
- Supabase RLS(보안 규칙)는 끄지 않는다.
- [A] 결제 금액은 **서버에서 상품 가격과 다시 대조**한다.
- [A] 구매자 전용 영상 링크는 결제 완료된 사용자에게만 보여준다.
- 실제 배포(`vercel --prod`)는 사용자 확인 후 실행한다.
